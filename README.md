# 多级供应链鲁棒库存优化

**Python · 混合整数规划 · 鲁棒优化 · 库存仿真**

当供应商提前期发生波动，制造企业应如何在多个环节配置库存？本项目构建多级库存研究原型：针对有限个提前期情景，求解一组共享的服务时间决策，控制最坏情景下的库存缓冲目标；并使用独立的物料流模拟器观察合成订单的交付与欠交过程。

> 项目处于研究原型阶段。仓库内示例均为虚构数据，目标值不是实际企业成本。

## 项目亮点

- **鲁棒优化建模**：将多情景下的服务时间、节点净保护期与需求缓冲曲线纳入混合整数规划，以最小化最坏情景的加权缓冲目标。
- **可扩展网络输入**：支持用户提供有向无环供应网络、节点权重、需求缓冲曲线、提前期情景和供应源服务时间上限。
- **物料流模拟**：以离散时间和十进制数量记录库存、在制品、订单交付和欠交；将当日满足与后续补交区分开。
- **结果核验**：对三节点合成算例，使用独立枚举核对优化目标；另有输入校验、库存账本与命令行测试。

## 一分钟看结果

演示网络由两个供应节点连接一个装配节点，比较名义、A 延迟、B 延迟三个情景。运行求解后：

| 指标 | 合成示例结果 |
| --- | --- |
| 最坏情景加权缓冲目标 | 4.7641 |
| 各情景目标（名义 / A 延迟 / B 延迟） | 3.4641 / 4.4641 / 4.7641 |
| 求解状态 | HiGHS 报告最优；独立枚举结果一致 |
| 测试 | 本地运行 20 项测试通过 |

数值只用于展示模型与程序的运行方式，不代表真实成本、节约金额或服务水平。

## 模型思路

对于节点 i 和情景 ω，以共享入站、出站服务时间 SIᵢ、Sᵢ 决定净保护期 τᵢω = SIᵢ + Tᵢω − Sᵢ。模型最小化各情景加权需求缓冲之和的最大值：

~~~text
min  max_ω  Σᵢ hᵢ · bᵢ(τᵢω)
~~~

约束包括网络上下游服务时间关系、每个情景下保护期非负、源点和末端边界，以及可配置的源点服务时间上限。需求缓冲曲线和情景为输入假设，不由模型自动估计。求解使用 SciPy 的 MILP 接口及 HiGHS。

## 快速运行

需要 Python 3.10+。在仓库根目录执行：

~~~bash
python -m pip install .
python -m inventory_lab.robust_demo
python -m inventory_lab.flow_demo --output outputs/flow_demo.json
python examples/read_flow_result.py --input outputs/flow_demo.json
~~~

物料流示例不覆盖已有文件，重复执行时请更换输出文件名。

验证：

~~~bash
python -m unittest discover -s tests -v
python -m unittest discover -s examples -p test_read_flow_result.py -v
~~~

## 研究背景与边界

研究稿以 [Willems 多级供应链案例](https://doi.org/10.1287/msom.1070.0176)为结构基准，分别映射外部销售或订单序列；网络与序列并非来自同一企业。研究中的评价期已有探索接触，不能视为盲测。稿件尚未达到投稿条件，结论不证明现实成本或服务改善。

由于第三方数据和部分案例材料的公开许可尚待核实，仓库不包含原始工作簿、订单明细或案例拓扑参数；论文中的内部证据材料也未随附，因此实证结果不能仅凭本仓库完整复现。公开求解器使用用户提供的网络，仓库示例为虚构数据。

本仓库尚未确定代码与论文的开源许可证；公开可见不等于授予再使用许可。
