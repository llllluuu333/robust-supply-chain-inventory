# 多级供应链鲁棒库存优化

[English](README_EN.md)

**Python · 混合整数规划 · 鲁棒优化 · 库存仿真**

当供应商提前期发生波动，制造企业应如何在多个环节配置库存？本项目构建多级库存研究原型：针对有限个提前期情景，求解一组共享的服务时间决策，控制最坏情景下的库存缓冲目标；并使用独立的物料流模拟器观察合成订单的交付与欠交过程。

> 项目处于研究原型阶段。仓库内示例均为虚构数据，目标值不是实际企业成本。优化与物料流模拟是独立模块，模拟器不自动接收优化策略，也不证明与保证服务模型等价。

## 项目亮点

- **鲁棒优化建模**：将多情景下的服务时间、节点净保护期与需求缓冲曲线纳入混合整数规划，以最小化最坏情景的加权缓冲目标。
- **可扩展网络输入**：支持用户提供有向无环供应网络、节点权重、需求缓冲曲线、提前期情景和供应源服务时间上限。
- **物料流模拟**：以离散时间和十进制数量记录库存、在制品、订单交付和欠交；将当日满足与后续补交区分开。
- **结果核验**：对三节点合成算例，使用独立枚举核对优化目标；另有输入校验、库存账本与命令行测试。

## 一分钟看结果

演示网络由两个供应节点连接一个装配节点，比较名义、A 延迟、B 延迟三个情景。运行求解后：

| 指标 | 合成示例结果 |
| --- | --- |
| 最坏情景加权缓冲目标 | 4.7641 |
| 各情景目标（名义 / A 延迟 / B 延迟） | 3.4641 / 4.4641 / 4.7641 |
| 求解状态 | HiGHS 报告最优；独立枚举结果一致 |
| 验证 | 合成算例通过独立枚举对照；测试命令见下方 |

数值只用于展示模型与程序的运行方式，不代表真实成本、节约金额或服务水平。

## 决策权衡示例

另一个虚构双供应商案例分别求解名义情景和三个有限情景的鲁棒模型，再将两组固定策略放到同一组情景中评价：

~~~mermaid
graph LR
    A[供应节点 A] --> M[装配节点 M]
    B[供应节点 B] --> M
~~~

按 A、B、M 的顺序，名义策略的入站服务时间 SI 为 (0, 0, 2)、出站服务时间 S 为 (2, 2, 0)；鲁棒策略的 SI 和 S 均为 (0, 0, 0)。时间单位为虚构日，两个方案分别在各自模型中求解后，固定策略逐情景回放。

| 策略 | 名义情景 | A 延迟 | B 延迟 | 三情景最坏目标 |
| --- | ---: | ---: | ---: | ---: |
| 名义策略 | 32.0711 | 40.0711 | 33.6603 | 40.0711 |
| 鲁棒策略 | 36.3137 | 38.8564 | 37.4940 | 38.8564 |

该示例中，鲁棒策略在名义情景下的目标较高，但在设定的三个情景中最坏目标较低。数字仅用于说明模型权衡，不是实际成本或对未来表现的保证。运行：

~~~bash
python -m inventory_lab.tradeoff_demo
~~~

## 模型思路

对于节点 i 和情景 ω，以共享入站、出站服务时间 SIᵢ、Sᵢ 决定净保护期 τᵢω = SIᵢ + Tᵢω − Sᵢ。模型最小化各情景加权需求缓冲之和的最大值：

~~~text
min  max_ω  Σᵢ hᵢ · bᵢ(τᵢω)
~~~

约束包括网络上下游服务时间关系、每个情景下保护期非负、源点和末端边界，以及可配置的节点服务时间上限。末端默认出站服务时间为零，也可以显式设置非负的承诺时间上限。需求缓冲曲线和情景为输入假设，不由模型自动估计。求解使用 SciPy 的 MILP 接口及 HiGHS。

## 快速运行

需要 Python 3.10+。在仓库根目录执行：

~~~bash
python -m pip install .
python -m inventory_lab.robust_demo
python -m inventory_lab.robust_cli --input examples/synthetic_robust.json --output outputs/robust_result.json
python -m inventory_lab.flow_demo --output outputs/flow_demo.json
python examples/read_flow_result.py --input outputs/flow_demo.json
~~~

两个文件输出命令均不覆盖已有文件；重复执行时请更换输出文件名。鲁棒结果记录输入文件的 SHA-256、Python/NumPy/SciPy 版本、时间限制、求解状态、上下界、服务时间和逐情景目标。哈希用于标识输入字节，不是数字签名，也不保证不同环境结果一致。退出码 0 表示通过求解器状态和数值容差的最优性检查，2 表示未通过该检查，1 表示输入或运行错误；这不是精确数学证明。

验证：

~~~bash
python -m unittest discover -s tests -v
python -m unittest discover -s examples -p test_read_flow_result.py -v
~~~

## 自定义网络输入

以 [合成 JSON 示例](examples/synthetic_robust.json)为模板：节点列表决定权重、缓冲曲线和各情景处理时间数组的顺序；edges 保存上游与下游的节点名称，网络必须无环。scenarios 中的 T 是各节点的非负整数处理时间；curves 是从零开始、随保护期非减的节点缓冲曲线，须覆盖模型计算出的最长保护期；source_service_caps 为必填的源点出站服务时间上限映射；没有上限时填写空对象 {}。 可选的 node_service_caps 可限制任意节点出站服务时间；可选的 terminal_service_caps 仅适用于末端，未指定的末端仍固定为零。同一节点有多个上限时取最小值。它们描述承诺时间，不能解释为产能或实际履约率。最多支持 32 个节点、128 条弧和 16 个情景。 各节点按最大处理时间计算的最长保护期不得超过 365；为避免求解器数值精度问题，模型也会拒绝过大的目标系数动态范围。请保持一致的时间单位；示例参数并非业务数据。 输入中出现未支持的字段会报错，避免将忽略的字段误认为已建模；当前未建模产能、运输与缺货成本。

## 研究背景与边界

研究稿以 [Willems 多级供应链案例](https://doi.org/10.1287/msom.1070.0176)为结构基准，分别映射外部销售或订单序列；网络与序列并非来自同一企业。研究中的评价期已有探索接触，不能视为盲测。稿件尚未达到投稿条件，结论不证明现实成本或服务改善。

由于第三方数据和部分案例材料的公开许可尚待核实，仓库不包含原始工作簿、订单明细或案例拓扑参数；论文中的内部证据材料也未随附，因此实证结果不能仅凭本仓库完整复现。公开求解器使用用户提供的网络，仓库示例为虚构数据。

本仓库尚未确定代码与论文的开源许可证；公开可见不等于授予再使用许可。
